# Cortex YOLO26s 3차 모델 통합 확인

> 최신 main 병합 전 검증 기록이다. 아래 Subtask 완료 시점과 테스트 개수는 당시 구현 기준이며,
> 최신 DONE→IDLE·계획 보정·H.264 적용 결과는 [최신 main 통합 확인](detector_main_verification.md)을 참고한다.

기존 `SYS-REQ-44-yolo-detector-integration` 로컬 브랜치에서 작업했다. 로봇에 명령을 보내거나 ROS를 구동하지 않았으며, 실제 모델 추론과 Cortex의 공통 판정·실행 로직을 오프라인으로 검증했다.

## 적용한 구성

- 모델: YOLO26s 3차 9/30 영상 기반 파인튜닝 (2차 모델 연속 학습)
- confidence 0.25, 목표 8 Hz, 최근 0.6초, 최소 3개의 서로 다른 프레임에서 과반 검출
- 가장 최근 처리 프레임에도 해당 객체 검출이 있어야 실행 허용
- 객체 확인 실패 시 최대 1초 동안 0.1초 이상 간격으로 재확인; 오류·미지원·시간 초과로 실행하지 않음
- 대기 중 정지 요청은 즉시 대기를 해제하고 VLA 명령을 보내지 않음
- 선택 가중치 SHA-256 확인; 냉장고·오이 존재만 확인하며 문 상태·완료 여부는 별도

## 근접 영상의 오이 존재 판정 비교

새 모델을 실제 어댑터로 추론하고 완료된 추론 시각의 204회 질의를 평가했다. 그 시각에 오이가 보이는 경우는 90회, 보이지 않는 경우는 114회다. 초기 확인 불가 2회는 미허용으로 포함했다. 보고서의 105장 평가·815프레임 평가와 다른 분모다.

| 판정 방식 | Recall | Precision | 부재 시 허용 | 보이는데 미허용 | 출현 후 허용 지연 | 사라진 후 차단 지연 |
| --- | --- | --- | --- | --- | --- | --- |
| 다수결만 | 95.6% (86/90) | 97.7% (86/88) | 2/114 | 4/90 | 0.341~0.370초 | 0.234~0.252초 |
| 다수결 + 최신 프레임 확인 | 93.3% (84/90) | 100.0% (84/84) | 0/114 | 6/90 | 0.341~0.370초 | 0.093~0.095초 |

confidence 0.25와 0.4는 이번에 처리한 프레임·질의 시점에서 같은 판정을 냈다. threshold를 최적화한 결과가 아니며, 0.25를 보고서의 초기 기준으로 유지했다. 최신 프레임 조건은 오래 남는 긍정 판정을 줄이는 대신 보이는 상황에서 미허용을 2회 늘렸다. 각 동작 시작 시 재확인할 수 있지만 모든 누락이 복구된다는 뜻은 아니다.

냉장고는 근접 영상 204회 중 초기 2회의 충분한 프레임 부족을 제외한 202회 모두 허용했다. 별도 시험 영상에서도 오이 허용은 없었다. 이는 각 영상에 대한 관측값이다.

## Subtask 재생

| 시나리오 | 확인한 동작 |
| --- | --- |
| 잠시 기다리면 오이가 보임 | open 0.4초 → pick 11.1초 → close 23.8초에 명령 발생 |
| 오이가 없는 시점에 pick 요청 | 최대 재확인 시간이 지난 뒤 계획 중단; pick·close 명령 없음 |
| VLA 완료 신호가 없음 | open 이후 다음 단계로 넘어가지 않음 |
| 확인 대기 중 정지 | VLA 명령 0건; 즉시 대기 종료 |

위 시각은 영상 재생 시각이며 작업 소요시간이 아니다. open 완료 10.6초·pick 완료 23.8초·close 완료 25.2초를 모의 입력했다. 첫 시나리오에서는 10.6초의 pick 확인을 11.1초까지 0.5초 기다린 뒤 명령을 보냈다. 카메라 영상은 녹화된 장면이므로 명령과 실제 영상 동작 사이의 인과관계는 없다.

## 검증 범위와 남은 확인

회귀 테스트 66개 통과, ROS 의존 테스트 1개 제외. 정지·대기·재확인·시간 초과·완료 전 다음 단계 차단·잘못된 모델 거부를 확인했다. 구문 검사와 저장소 기존 CRLF 형식을 고려한 변경 검사도 통과했다.

기존 test를 재사용한 탐색 검증이다. 관측한 문제를 바탕으로 판정 방식을 수정했으므로 별도 KIST 실행 기록으로 재검증해야 한다. 부재 시 허용 0회는 표에 포함된 질의 시점에서의 결과이며, 추론 사이의 시간 전체에서 잘못된 허용이 없다는 보장이 아니다. 입력 끊김은 기존 프레임의 유효시간이 지난 뒤 확인 불가로 전환된다.

ROS Humble 빌드·생성 메시지·실제 카메라 QoS와 시각 동기화·실제 VLA 연결·RTX 4090 전체 지연은 미검증이다. 서비스 호출의 지연과 실행기 tick 주기 때문에 시간 초과 통지가 늦어질 수 있지만, 확인 기한을 넘긴 긍정 응답으로 명령을 보내지는 않는다.

실행 방법은 `docs/detector_v3.md`, 재현 도구는 `scripts/verify_detector_offline.py`와 `scripts/replay_preconditions.py`를 참고한다.
